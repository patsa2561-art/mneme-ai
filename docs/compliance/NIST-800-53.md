# NIST SP 800-53 Rev 5 — Mneme Control Mapping

*Security and Privacy Controls for Information Systems and Organizations · v1.11.0*

This document maps Mneme's v1.11.0 capabilities to NIST 800-53 Rev 5 controls relevant to a developer toolchain. Useful for FedRAMP, FISMA, and DOD ATO environments.

## Control families & coverage

### AC — Access Control

| Control | Implementation |
|---|---|
| **AC-3** Access Enforcement | Daemon PID file ownership check refuses cross-user access (POSIX uid match). PID file mode 0600. |
| **AC-6** Least Privilege | `.mneme/audit-log.secret`, `.mneme/audit.log` written mode 0600. |
| **AC-17** Remote Access | Out of scope — Mneme is local-first; federation hub deployment is customer-managed. |

### AU — Audit and Accountability

This is Mneme's strongest 800-53 alignment.

| Control | Implementation |
|---|---|
| **AU-2** Event Logging | `mneme audit-log enable` logs all 19 mutating action types. |
| **AU-3** Content of Audit Records | Each entry: ts, actor, action, target, details, prevHmac, hmac. |
| **AU-6** Audit Record Review | `mneme audit-log show --json` exports for SIEM ingestion. |
| **AU-9** Protection of Audit Information | HMAC-SHA-256 chain — modification detected by `mneme audit-log verify`. File mode 0600. |
| **AU-9(3)** Cryptographic Protection | HMAC-SHA-256 (FIPS 198-1) over canonical JSON of each entry, chained via prevHmac. |
| **AU-10** Non-repudiation | Audit entries can be cryptographically attributed to the secret-holder. Combined with Ed25519 export signing for off-system attestation. |
| **AU-11** Record Retention | Customer-controlled via `mneme audit-log rotate` + filesystem retention. |
| **AU-12** Audit Generation | Entries auto-appended on every state-changing CLI/MCP operation. |

### CM — Configuration Management

| Control | Implementation |
|---|---|
| **CM-5** Access Restrictions for Change | `mneme key rotate` requires explicit `--confirm`. Default is dry-run. |
| **CM-6** Configuration Settings | `mneme audit-log config` is a separate file (.mneme/audit-log.config.json) under audit-log control. |

### IA — Identification and Authentication

| Control | Implementation |
|---|---|
| **IA-5** Authenticator Management | Audit secret rotation via `mneme key rotate --confirm` re-signs entire chain atomically. Old log archived (never destroyed). |
| **IA-7** Cryptographic Module Authentication | `mneme --compliance fips140` refuses to start if Node OpenSSL is not in FIPS mode. |

### SC — System and Communications Protection

| Control | Implementation |
|---|---|
| **SC-8** Transmission Confidentiality | Federation envelopes signed Ed25519 (FIPS 186-5). TLS deployment is customer responsibility for the federation hub. |
| **SC-12** Cryptographic Key Establishment | Vault uses scrypt KDF (RFC 7914) with N=2^17, r=8, p=1, 256-bit derived key. |
| **SC-13** Cryptographic Protection | Only FIPS-approved algorithms used. See `core/security/compliance` for the inventory. |
| **SC-17** Public Key Infrastructure Certificates | Federation uses bare Ed25519 public keys (RFC 8032) — not X.509 — by design (avoids a CA dependency). |
| **SC-28** Protection of Information at Rest | `core/security/vault` AES-256-GCM (FIPS 197 / SP 800-38D). |

### SI — System and Information Integrity

| Control | Implementation |
|---|---|
| **SI-7** Software, Firmware, Information Integrity | `MNEME_PINNED_MODEL_CHECKSUMS` provides SHA-256 verification of bundled WASM models. Refuses to load tampered model. |
| **SI-7(1)** Integrity Checks | Run on every embedder bootstrap (cache verified before pipeline init). |
| **SI-10** Information Input Validation | MCP runtime rejects shell metacharacters in subprocess args; vault rejects malformed envelope structure; audit log rejects non-JSON entries during verify. |

### SR — Supply Chain Risk Management

| Control | Implementation |
|---|---|
| **SR-4** Provenance | npm publishes use provenance attestation. Git tags signed. |
| **SR-9** Tamper Resistance and Detection | WASM model checksum (SI-7); audit log HMAC chain (AU-9(3)). |
| **SR-11** Component Authenticity | `mneme deps-audit` enumerates dependency provenance. |

## FedRAMP-relevant deployment notes

A FedRAMP-Moderate baseline customer should:

1. Set `OPENSSL_FIPS=1` and validate Node is built against FIPS-validated OpenSSL.
2. Run all Mneme commands with `--compliance fips140`.
3. Wire `MNEME_AUDIT_SECRET` to a FedRAMP-authorized key vault (AWS GovCloud KMS, Azure Government Key Vault, etc.).
4. Schedule `mneme audit-log verify` as a hourly CI gate (alert on non-zero exit).
5. Pin the embedder WASM model checksum in `MNEME_PINNED_MODEL_CHECKSUMS`.
6. Disable federation (default) for any deployment in an authorisation boundary.
