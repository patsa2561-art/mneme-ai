# AI Session Audit — `mneme audit` (v0.27)

> **Every AI-driven commit gets a trust certificate.** Vendor-neutral. Works with Claude Code · Cursor · Codex · GPT-5.5 · Sweep · Devin · Aider · any tool that ends up in `git log`.

═══════════════════════════════════════════════════════════════════════════════

## TL;DR

AI tools silently introduce regressions. They claim "I added X without touching Y" — then the diff shows three lines in Y. Tests pass; behavior changed; nobody noticed.

`mneme audit` snapshots behavior **before** the AI works, traces what actually changed **after**, verifies the AI's commit-message narrative against the **actual diff**, and produces a **5-axis trust certificate**. Suitable as a CI gate; suitable as a compliance audit trail; suitable for "I don't trust this AI yet" personal review.

═══════════════════════════════════════════════════════════════════════════════

## Six modes — copy-paste flow

```bash
# 1. Before you let an AI loose:
mneme audit --baseline

#    → Claude Code / Cursor / Codex / etc. does its work →

# 2. See what it did (vs. what it CLAIMED):
mneme audit --trace        # diff + AI vendor detection
mneme audit --verify       # narrative vs reality

# 3. Decide if you trust it:
mneme audit --certify      # 5-axis pass/warn/fail · exit 1 on fail · CI-friendly

# 4. Continuous gate (CI):
mneme audit --watch --interval 60

# 5. Compliance / audit trail:
mneme audit --report --out audit-2026-q2.md
```

## What gets checked — the 5 axes

| # | Axis | What it asks | Verdict logic |
|---|---|---|---|
| 1 | **Behavioral parity** | Did `mneme status / htc-stats / npm test` produce the same output? | Mismatch on critical commands → fail |
| 2 | **API contract drift** | Did exported types / functions disappear? | Removed export → fail · Renamed → warn · Added → pass |
| 3 | **Test pass rate** | Any test that passed before, fails now? | Any new failure → fail |
| 4 | **Perf regression** | Median latency vs baseline | >25% slower → fail · >10% → warn |
| 5 | **AI narrative** | Commit message claims vs git diff | Any "contradicted" claim → fail |

Plus **forensic axes** (the same anomaly engine Mneme runs on human commits, applied to AI commits):

- `size` — much larger than this AI's typical commit?
- `files` — touched files this AI never touches?
- `style` — verb pattern off-brand for this AI?
- `time` — anomalous time-of-day for this AI?

## What "AI narrative verification" looks like

A real example. Suppose the AI commits:

```
feat: add JWT issuer to auth middleware

Adds an issuer field to JWT validation. No changes to db.ts or session.ts.
```

…and the diff actually touches:

```
src/auth/middleware.ts   +18 -3
src/db.ts                +3  -0
src/auth/jwt.ts          +12 -2
```

`mneme audit --verify` catches:

```
⚠ ai-narrative-mismatch  1 contradiction
   AI claimed: "No changes to db.ts"
   Reality:    db.ts was modified (+3 -0)
   Verdict:    contradicted
```

The AI may have been right that the change to `db.ts` is unrelated. Or it may have silently fixed a bug it doesn't realize is breaking. Either way **the human sees the gap**.

## How AI vendors are detected

Mneme reads each commit's message + author email and matches:

| Pattern | Vendor |
|---|---|
| `Co-Authored-By: Claude` | claude-code |
| `[Cursor]` in message | cursor |
| `Generated by Codex` | codex |
| `noreply@anthropic.com` author | claude (any flavor) |
| `noreply@cursor.sh` author | cursor |
| `devin.ai` reference | devin |
| `sweep.dev` reference | sweep |
| `Aider:` prefix | aider |
| no AI marker | human (skipped or low-confidence flag) |

**Vendor-neutral by design.** Adding a new AI = one regex line. Mneme audits whatever the AI claims it is.

## Why it's in Mneme (not a separate tool)

`mneme audit` reuses **everything we already built**:

- 📦 **HTC compressed memory** — the AI's changes are evaluated against 50K commits of compressed context
- 🔬 **Leviathan citation verifier** — generalized to "narrative vs diff"
- 🛡 **Forensic anomaly engine** — same axes (TIME / FILES / STYLE / SIZE), AI commits get scored like human commits
- 📰 **Iris pyramid renderer** — 5-axis certificate output is journalist-grade
- ⚡ **SuperPipeline + MPE** — multi-axis evaluation runs in parallel; converges on YOUR repo's perf characteristics

A standalone tool would have to build all of these from zero.

## CI integration — `audit --certify` as a gate

```yaml
# .github/workflows/ai-audit.yml
name: AI Audit
on:
  pull_request:
    types: [opened, synchronize]

jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - run: npm install -g mneme-ai
      - run: mneme audit --baseline
      - run: mneme audit --certify
        # exit 1 on fail → PR check fails
```

Works with **any AI** that touches the PR. Vendor-neutral.

## What this is NOT

- **Not a replacement for human code review.** It catches mechanical regressions; humans still judge taste, security, architecture.
- **Not a replacement for your test suite.** It runs alongside; tests are one of the 5 axes.
- **Not vendor-locked.** Works with any AI, any language, any IDE.
- **Not an LLM-grader.** No "AI grading AI" loops. Pure rule-based + statistical primitives — same kind that powers `mneme forensics`.

═══════════════════════════════════════════════════════════════════════════════

## Honest limits

- **Narrative verification is heuristic.** "No change to db.ts" is parseable; "improved overall reliability" is not — Mneme marks it `unverifiable`, doesn't pretend.
- **Behavioral parity needs a stable baseline.** First commit after `--baseline` will have zero noise; weeks-old baselines get noisier as the repo drifts.
- **Forensic axes assume baseline data.** A new AI vendor needs ~5 commits of history before its anomaly axes are meaningful. Audit will flag "insufficient baseline" instead of false-flagging.
- **Single-author repo limit.** Anomaly axes lose meaning if all commits come from one AI. Audit surfaces this with a `HEADS UP` pill.
